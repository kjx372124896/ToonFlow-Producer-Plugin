# ToonFlow 短剧制片管理中心 · 节点插件 v0.9.0

**安装文件仅为 `dist/producerStudioNode.umd.js`。** 它是用 `D:\Toonflow-app\packages\nodeScaffold` 官方节点脚手架生成的 ToonFlow 节点插件，适用于设置里的 **节点插件** 安装入口。

> 原来的 `ext-producerStudio.umd.js` 是文档扩展，不兼容节点插件安装入口，已移动到 `archive/`，切勿选择它。

## 已实现的 MVP
1. 在无限画布添加「短剧制片中心」节点，点击「打开制片中心」进入全屏界面。
2. 创建独立项目：默认以当前画布工作区为根目录，每个项目拥有独立的 <项目名-ID>/项目.tfprod、assets/、novel/。允许选择工作区内的自定义相对子目录、切换其他独立项目。
3. 完整内置从 ToonFlow 1.1.8 原目录复制的 11 套视觉手册和 12 套导演手册，保留 168 个原始 Markdown 章节；内置手册只读，可复制编辑，自定义预设持久化在工作区 producer-manuals/。
4. 小说 TXT 导入本项目 novel 文件夹、自动拆章、章节事件规则初提；简单改编成可编辑剧本。
5. 从剧本识别初版角色 / 场景 / 道具资产，新项目图片保存在本项目 assets 文件夹。
6. 选择剧本生成分镜面板，关联角色与资产，修改镜头提示词。
7. 画布装配直接使用节点所在画布上下文，无需 MCP；文本始终用模型文本节点，并可在项目设置里指定默认文本模型。图片、视频可分别使用模型节点（选择具体默认模型）或已保存的 RH 工作流节点（选择 RH 应用 UID），不自动执行生成。
8. 从 ToonFlow 自身 `/api/ai/models` 和 `/api/ai/media/models` 获取文本、图片、视频、音频模型清单，按提供商及模型名称选择。选择后保存提供商 ID + 模型 ID；画布装配通过原生图片/视频节点 setConfig 写入并校验，文本节点通过同画布 VueFlow 数据层设置 `data.model` 并写后校验。留空则沿用各节点自身默认模型。
9. 旧版项目文件可选择迁入独立文件夹：保留原始项目文件，复制相关小说、资产并校验，保存分镜绑定。已生成画布节点如果切换模型/RH 方式，要求确认后重新装配，不静默复用旧节点。
10. v0.4.0 新增 **音频生成** 默认配置：默认关闭，支持按项目选择音频模型或 RH 已保存应用。选择 RH 时，在每个分镜旁创建「音频文案 → RH 音频」节点，连接进视频生成节点，且不会自动触发任务；关闭音频的旧项目维持原装配。**当前 ToonFlow 自带的 audioNode 仅是素材节点**，并非音频生成节点，因此使用音频模型必须安装兼容的 `audioGenerationNode` 才允许画布装配；否则在改动画布前明确报错。RH 应用必须实际支持音频输出。
11. **v0.5.0 小说与事件分析**：小说页改为宽屏章节表格，支持 TXT/MD 导入、编码、章节搜索、分页、逐章编辑、复选批量删除和查看事件详情。事件分析调用 ToonFlow 已配置的文本模型，走原生 `/api/ai/models` 和 `/api/ai/generate` SSE 接口；不会向外部暴露 API Key，不再用规则抽取冒充模型分析。
12. 事件分析采用用户指定的 **严格 7 字段单行竖线格式**：章节、涉及角色、核心事件、主线关系、信息密度、预估集长、情绪强度。原需求中「涉及场景」将格式变为 8 字段，且两个示例均为 7 字段，因此优先遵守最高优先级与示例，暂不单独输出场景。字段格式、章节匹配、30-60 字摘要及情绪标签进行校验；若格式错误仅再调用模型一次，不对网络错误自动重试。每章保存结构化结果、原始输出、模型、时间戳及失败错误；失败可选择重新分析，重新编辑原文的旧结果标为待重新分析。
13. 默认仅分析未完成/失败/过期章节；勾选具体章节可以强制重新分析。支持任务停止、统计成功/失败、逐批落盘；v0.6.0 使用并发任务队列替代旧版串行批处理。模型分析需要实际配置供应商，会消耗模型费用。真实模型生成和多章节负载需要在 ToonFlow 正在运行的环境中验证。
14. **v0.6.0 并发队列**：项目设置新增文本、图片、视频、音频四类独立并发上限（1–100）及失败重试次数（0–5）；旧项目缺失该项时使用默认值（文本5、图片3、视频2、音频3；每类重试2次）。小说分析已从串行切换为并行工人池，数百章可一次加入队列，超额等待、完成自动补位、失败退避并回到队尾重试；超过上限的失败任务保留错误供手动重试。
15. 本项目 `taskQueues.text` 持久化每章 ID、原文指纹、模型、运行状态、尝试次数与失败原因；开始前保存队列、过程中将短时间完成的任务合并保存，页面关闭/插件刷新后自动恢复待完成队列，已成功内容不会自动重做。关闭界面会暂停本地任务，**不是后台服务**，需要重新打开界面才能继续。已增加 500 章、100 并发、自动重试、断点恢复与项目隔离测试。
16. 媒体队列的配置与通用调度器已可用，但当前**尚未挂接实际图片、视频、音频任务执行入口**：画布装配不会擅自触发收费媒体生成；需要后续在媒体生成流程调用该队列，才能对实际媒体生成生效。
17. **v0.7.0 事件提取规则库**：小说管理页事件分析按钮旁新增「提取规则」快捷入口；模型下方可选择【内置】或【自定义】规则、快速新增，支持编辑、另存为新规则、删除。原七字段指令保留为不可覆盖的内置规则；编辑内置规则自动创建副本。自定义规则文件保存在 ToonFlow 画布工作区 `producer-rules/事件提取规则.json`，可跨项目复用；所选规则 ID 存在项目 `project.eventRuleId`。规则数据损坏时不会静默覆盖旧数据。
18. 每批章节提交时将 `rule: { id, name, prompt, digest }` 快照写入 `taskQueues.text[]`，调用 ToonFlow 文本模型时把 `job.rule.prompt` 作为 systemPrompt，重试及恢复也保持原规则；事件记录回写规则 ID、名称、正文指纹。修改当前规则后，旧成功事件标为「待重新分析」；同章节使用新规则可再次入队。**结构化输出协议仍固定为原约定的七字段**，自定义提示词应保持该格式，否则按原协议校验并记录失败。真实供应商下的运行效果仍需要实测。
19. **v0.8.0 剧本管理**：剧本页拆成「剧本生成 / 剧本管理」双选项卡。生成页可以单选、多选章节合并为一集，筛选章节并展开预览合并原文，设置目标时长（15–3600 秒）、集数、标题、首次改写要求（可空），使用 ToonFlow 自带文本模型生成专业场次剧本。系统提示词按 `1-1 苏鸾寝殿 夜 内` 场景头、`△ ` 动作、`角色：台词` 规范输出，优先保留原著对白、忠于事件因果，按目标时长控制节奏；验证场次连续性，不接受说明性 Markdown 伪结果。
20. 在「剧本生成」中多轮提交修改意见时，模型每轮读取原文、上一版完整剧本与反馈，生成完整修订版本，保留最多 30 条历史版本，可直接编辑/恢复版本。工作稿保存在项目 `scriptWorkspace`，与 `scripts` 正式剧本库严格隔离；关闭窗口/刷新后可继续编辑，生成中关闭页面会取消当次请求。**只有点击「确认保存为一集剧本」**，才写入 `scripts` 列表、生成 `scenes`、关联来源章节/事件，并创建当前项目 `scripts/第NNN集-<id>.txt` 独立文件，读取验证后保存项目索引；禁止覆盖同集数或在原文变更后静默入库。
21. 「剧本管理」显示已入库剧本的集数、标题、来源章节、目标时长、场次和状态，支持搜索、全屏编辑、保存更新及删除索引；编辑后写回原 TXT，保持 script ID 不变，供既有资产提取与分镜制作使用。已生成的分镜不会被编辑剧本时静默覆盖，删除带分镜剧本需二次确认，独立 TXT 作为历史备份保留。旧版单章脚本仍能显示编辑。真实模型的时长控制与长文本负载需在 ToonFlow 正在运行的环境中验证。
22. **v0.9.0 剧本批量导出**：在「剧本管理」勾选一集或多集，按集数排序打包到一个 ZIP，内部为带中文标题的 UTF-8 TXT； ZIP 使用标准 PKZIP/CRC32 格式，已通过 Windows .NET ZIP 实际解压验证。未选中的剧本不会导出。
23. **v0.9.0 AI 提取资产**：在剧本管理勾选剧本并点击「提取所选剧本资产」，跳转到分类资产库并使用项目默认文本模型逐集抽取。角色、场景、重要道具只提取需要一致性的元素，返回含描述、别名、身份线索的 JSON。遵循项目文本并发上限，待确认结果保存在 `assetExtractionDrafts` 中，审核时可选择明确新建或绑定到已有资产，点击确认后才写入 `assets` 和 `assetMentions`。
24. **实体身份复用和消歧**：一个资产只有一个 canonical `id`，不同集的相同正式名称默认复用；大师兄、掌门、师尊等称呼即使完全相同也不自动按名字归并，允许每一集将其绑定至苏荷、张三或另一个新实体；两份已存在的同类别资产可手动合并，合并引用、别名、图片、音频和已建分镜 ID。分镜按当前剧本来源匹配别名，不因同名宗门头衔误绑定其他集人物。
25. **资产分类与媒体版本**：支持角色/场景/道具分类、指定第 N 集筛选、缩略图及完整媒体详情。每个资产保存 `images[]` / `audios[]` 和当前 `defaultImageId`，`imagePath` 继续兼容旧分镜装配链路。可上传多图、选择默认图、删除具体图、编辑描述/身份/别名和删除资产；生成新图片保留此前版本。老项目只有 `imagePath` 的资产会在打开资产库时补齐单张历史图片记录。
26. **图片和配音生成**：图片模型通过 ToonFlow 原生 `/api/ai/media/generate` 实际提交并保存返回的工作区文件路径；图片和音频都可调用画布 RH 工作流节点，自动选择已保存应用，将资产描述（配音使用输入台词）写入真实 RH 文本参数并读后校验，再执行工作流和收集实际媒体文件；若应用不支持文本字段或输出类型不匹配则明确报错，不伪称成功。**当前 ToonFlow 服务器只开放 image/video 模型生成接口，尚无原生音频模型生成端点，配音暂通过 RH 音频工作流**。应用真实生成和上游供应商并发仍需在当前用户环境中端到端验证。


## v1.0.0 专业分镜表与完整分镜板

剧本和资产完成后，可选择第 N 集调用 ToonFlow 文本模型生成专业镜头表。镜头表支持手动编辑景别、机位、运镜、动作、台词、光线、声音、转场、时长、视频模型（minimaxH3 / seedance2.0）和参考模式（首尾帧 / 全能参考）；分镜图可按图片模型选择生成或跳过。勾选多个镜头后，插件按顺序合并为一个完整分镜板并计算总时长（例如 1+3+7=11 秒），将镜头段落、参考资产及图片版本提交给文本模型生成视频提示词。分镜板状态、镜头表、资产缩略图、资产版本、提示词均可审核和编辑，确认后以一个完整制作单元装配到 ToonFlow 新版画布。
## 安装
- 打开 ToonFlow：设置 → 插件市场 → 安装节点插件（或节点插件管理）
- 选择本目录 **`dist\producerStudioNode.umd.js`**。
- 安装成功后，在无限画布添加节点「短剧制片中心」，打开它的全屏管理界面。
- v0.3 新项目保存在当前画布工作区 `<项目名-ID>/项目.tfprod`，素材分别保存在同目录的 `assets/`、`novel/`。旧版 `producer-studio/<节点ID>/` 不会自动删除，需在项目设置中使用安全迁移按钮。
- 画布联动直接依赖当前制片节点所属的无限画布，不需要 MCP 地址或密钥，也不会自动发起媒体生成。
- 重新安装或更新插件后，刷新画布再打开原制片节点；原工作区中的项目数据和分镜记录保持不变。

## 稳定版部署
当前实际使用的 ToonFlow：`D:\toonflow-stable`；节点加载目录：`D:\toonflow-stable\data\nodes`。

运行 `npm run build:stable` 会构建并部署 `producerStudioNode.umd.js` 到该加载目录，自动在本项目 `archive/` 中备份旧插件，并校验文件 SHA-256。部署后先保存当前工作区，再完全退出并重新打开 ToonFlow，以加载更新后的插件。稳定版画布使用按需查询的 v3 接口，不能复用旧版一次读取全量节点的代码。

## 构建
工作目录：`D:\ToonFlow-Producer-Plugin`。
当前构建器需要相邻目录 `D:\Toonflow-app` 及其中的已安装依赖。

```powershell
cd D:\ToonFlow-Producer-Plugin
npm run check
```

`npm run build` 只生成可安装的 **节点版**，不会再误生成文档扩展。
老版文档扩展源码仍保留为兼容参考。

## 验证边界
- 构建器来自当前本地仓库的官方节点脚手架；安装器要求的元数据、导出标识和 JavaScript 语法会被自动核验。
- 事件抽取、改编与资产识别是规则 MVP，不是大模型精细改编。
- 画布装配已有自动化模拟测试，包括模型与 RH 混合模式、音频 RH 分支、复用节点、类型兼容和画布切换防误写。全量 42 分镜、RH 应用真实运行仍需要在正在使用的 ToonFlow 中验证；测试模拟不代表媒体任务真实运行成功。
- 旧版手册内置 **完整 Markdown 内容**；旧版手册封面/图库图片未内嵌在单文件插件中（总计约 20MB）。
- 不修改 ToonFlow 核心源码。插件独立维护。
